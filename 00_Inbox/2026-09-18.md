## 1. Claude Code Projects 改版：值得对照 Kanban，但暂不能替代本地执行

【事实】已核验 9 月 17 日 Claude 官方公告：新版 Projects 由主对话协调拆解、并行线程、结果审查与汇总；线程是各自使用独立分支及仓库副本的 Claude Code 云端会话，并共享项目记忆。初始 beta 只面向部分使用云端会话、且网页或桌面端没有既有项目的 Pro/Max 用户；官方计划逐步扩大范围。当前线程在云端运行，本机执行仍是后续计划。官方特别提醒：并发线程可能更快触及使用额度；代码重叠仍需解决合并冲突。

【影响】这与我们的“项目卡→分工执行→验收”高度重合，可作为现有 Kanban 编排的对照候选。判断：它可能减少手动交接，但不是自动消除冲突、保证验收或无限后台执行。投资系统依赖的本地数据、外置盘和凭证不能假定云端可直接访问；小说的 profile/model 组合评测也不能由共享记忆直接取代。

【动作】建议保留 Hermes 主控与现有 Kanban；账号出现入口后，只用不含凭证和敏感数据的独立代码任务比较交接负担、合并冲突、验收证据与额度消耗，再判断是否接入。不要为获得 beta 删除既有项目，不为试用迁移生产资料。已采取：将 AI HOT、官方博客及个人关注源的同事件合并，核清云端限制与灰度条件；未启用云任务、上传仓库或更改现有编排。

【证据】[Claude 官方原文](https://claude.com/blog/projects-redesigned)；聚合线索署名：[AI HOT](https://aihot.news/items/cmu5tujnp0jvoroqoq64oqnjr)。

【可信度/待核验点】产品机制、公告日期及初始可用条件已由第一方确认；昱桥账号资格、后台运行边界、共享记忆准确性和实际交付成本未实测。此事件不同于昨日的 Cowork/聊天合并，不重复推荐文档和 PPT 入口。

## 2. Codex 新增用量归因：先找额度消耗来源，再谈“省额度技巧”

【事实】已通过网页核验 OpenAI Developers 官方帖：可查看任务、子 Agent 和单独聊天对 Codex 用量的贡献。该帖没有充分说明套餐覆盖、具体入口或统计口径，不能据此声称本账号已可用，也不能等同于美元账单或额度增加。

【影响】我们依赖 Codex 做工程和验证；判断：相比凭感觉减少上下文或照搬社交平台的“省额度技巧”，先定位耗量任务更有决策价值。额度消耗应与通过验收的产出对应，不能只追求单次对话便宜而增加返工。

【动作】建议下一次 Codex 工程任务中，若账号已有入口，记录任务及子 Agent 的用量贡献，并连同返工和测试结果复盘；优先检查重复读上下文、无效重试与不必要并发。先观察再调工作流，不追加付费。已采取：回官方原帖确认，将未核验的“网页规划不占 Codex 额度”等社区断言排除出结论；未调整订阅或运行计费实验。

【证据】[OpenAI Developers 官方原帖](https://x.com/OpenAIDevs/status/2100733364877803741)。

【可信度/待核验点】官方宣布用量归因能力已证实；本账号可用性、统计延迟、覆盖范围与实际节省效果待核验。本次没有账号侧实测，不能报告节省比例。
