## 1. Cursor 事故复盘：历史 Agent 记录里的密钥，也能成为攻击入口

【事实】已核验 Cursor 最新复盘及 Fireworks 更新通告。按 Cursor 的调查，攻击者获得其签发给 Fireworks 的访问密钥，复制共享存储中的历史编程 Agent 记录；其中少量记录含未脱敏凭据，随后被用于进入 Cursor 的部分内部服务，攻击链最终涉及扩展分发缓存被篡改。这是相对 10 月 31 日雷达新增的泄露链路，不是今天发生了另一轮插件攻击。Cursor 称事件已得到控制，当前实时推理请求、客户代码仓库和官方应用更新不在其列出的受影响范围内；这些是厂商调查结论，不是独立取证保证。

【事实】补正此前版本范围：本次核验的官方通告列出 Anthropic.claude-code 2.1.312 和 2.1.313，限涉事时段经 Cursor VS Code 扩展市场分发的恶意构建，不能仅凭版本号判定感染。10 月 31 日雷达仅记录了 2.1.313；官方通告注明已于 10 月 30 日更新范围，因此这里是更正旧记录，不把它包装成新披露。

【影响】对 Hermes＋Codex＋Claude Code 主栈，改变的是安全检查范围，而不是换模型：当前没有恶意插件，不代表过去上传到会话、调试记录或支持附件中的凭据没有暴露。若交易、研究或客户项目的密钥进入过这些记录，风险可能越过编辑器边界；本次没有证据证明昱桥存在这种暴露，也不能把事件扩大为 Claude Code 官方发行渠道被攻破。

【动作】已完成本机只读定点复查：当前 ~/.cursor/extensions 无名称含 claude 的条目；~/.ssh/authorized_keys 不存在；~/.config/.smt、~/.config/.smtk 和 ~/Library/LaunchAgents/com.apple.sysmond.plist 均不存在。未删除文件、运行远端修复脚本或轮换凭据。建议维持现有主栈，把密钥从对话、工具日志与支持附件中隔离；若收到厂商针对具体凭据的泄露通知，或历史安装记录命中涉事构建，再按官方指引隔离、排查持久化，并从可信设备轮换相应凭据，不因泛化恐慌无差别重配所有账号。
