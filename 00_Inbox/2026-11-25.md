## 1. OCRia-nano-1：本地文档解析新候选，商业授权不能只看公司规模

【事实】已核验 LlamaIndex 公告与模型卡：OCRia-nano-1 通过 LiteParse 在本地 CPU 上进行文字、表格和版面解析，支持中日韩文字，输出 Markdown 或带位置坐标的 JSON；没有图表转数据表能力，图表保留为图片。模型许可证与 LiteParse 的 Apache 2.0 许可证分开：附件 A 对上一年总营收或累计股权／债务融资超过 200 万美元的主体设有限制，个人使用和规定的研究用途有例外；即使未超过门槛，用于与 LlamaParse／LlamaCloud 竞争的文档解析、OCR 或抽取产品／服务，除研究用途外仍须另获许可。不是“小公司就能任意免费商用”。

【影响】投资研究的政策原文、公告和供应链资料，新增了可在本机承担基础解析的候选；复杂图表仍需升级处理，不能把解析结果直接当作交易证据。若将它打包进对外客户服务，授权边界可能比算力成本更先成为障碍。

【动作】已核对模型卡和完整许可证，不采用厂商跑分作为本机效果。建议仅列入现有资料入库链路的对照评测：用公开中文 PDF 检查漏字、跨页表格、单位和页码定位，合格后再考虑接入；对外产品先核验竞争性用途和客户主体资格。本次未下载模型、安装依赖或改动生产流程。

【证据】[LlamaIndex 官方公告](https://www.llamaindex.ai/blog/introducing-ocria-nano-1)；[官方模型卡：能力与图表限制](https://huggingface.co/llamaindex/OCRia-nano-1)；[完整模型许可证，重点看附件 A](https://huggingface.co/llamaindex/OCRia-nano-1/blob/main/LICENSE)。

【可信度/待核验点】官方公布的能力和许可文本已核验；中文材料准确性、本机吞吐、与现有解析器的收益差异未实测。具体商业项目是否属于竞争性服务，不能仅凭本报告认定。

## 2. SubCast：播客可交给 Agent 处理，但“本地识别”不等于“不外传”

【事实】已核验作者新增 MCP／CLI 的公告；仓库源码存在字幕获取、基于字幕问答、提取高光和导出剪辑的工具实现，不只是产品预告。官网同时明确：识别后的字幕、译文和导读默认匿名共享，可在设置中关闭；云端识别、AI 问答和翻译会向所选服务商发送所需内容，接口费用另计。发行说明还提示，命令行不可用时可能自动向 shell 启动文件添加 PATH 配置。

【影响】它可作为“完整播客文字稿 → 可回到时间点的研究摘录 → 素材剪辑”的候选组件，接在现有 Agent 工作流后，而非再换一套助手。真正价值是减少音视频研究搬运，不是多生成一份摘要；默认共享和云调用意味着它不能直接承接客户录音或私密材料。

【动作】已核对公告、工具源码、隐私说明与发行记录。建议先只用公开节目评测，关闭匿名共享并核对云调用去向；验收时保留完整文字稿、原始链接和时间点，抽查摘要是否遗漏限制条件，不能把模型导读冒充原话。剪辑能导出不等于有转载商用权。本次未安装、注册 MCP、修改 PATH 或上传材料，不替换现有 SenseVoice。

【证据】[作者原始公告](https://x.com/vista8/status/2125244592614506880)；[MCP 工具源码](https://raw.githubusercontent.com/joeseesun/subcast/main/crates/subcast-cli/src/cmd/mcp.rs)；[官网隐私与共享开关说明](https://subcast.qiaomu.ai)；[发行说明：命令行与 PATH 行为](https://github.com/joeseesun/subcast/releases/tag/v0.3.5)。

【可信度/待核验点】公告、源码中的工具实现及文档声明已核验；本机运行、剪辑质量、长节目完整性、共享开关对各条处理路径的实际效果待测。未证实“任意视频都能处理”，也未把源码存在等同端到端验收通过。

## 3. gflow-cli：能串起视频生成，但不该拿主账号换自动化便利

【事实】已实际解析实践帖短链，确认指向 ffroliva/gflow-cli。项目文档声明可经 CLI／MCP 驱动本人已登录的 Google Flow 会话，并消耗账号的视频生成积分；它不是 Google 官方工具。维护者的账号安全说明明确承认自动化存在账号风险，测试账号未观察到封禁不构成保证。当前 README 提供 `gflow mcp run --no-spend`，声明该模式不注册消耗积分的工具；这只是支出限制，不是账号安全保证。

【影响】小说宣传片或视频素材确有减少手工操作的空间，但“会员积分别浪费”不能推出“应当自动化跑满”。昱桥把账号封禁风险设为硬边界，因此这条路径当前不适合主账号和无人值守生产；积分是已有权益，也不等于可以无授权消耗。

【动作】已将该线索判为暂不接入主流程，未安装工具、登录账号或生成视频。不采用“积分完全够用”“一条龙就能商业化”的推广结论。出现真实出片需求时，先核验官方支持的生成路径、使用条款和单片预算；不得把禁支出模式当作可放心登录的理由。

【证据】[项目 README：集成与禁支出模式](https://github.com/ffroliva/gflow-cli/blob/main/README.md)；[维护者账号安全说明](https://github.com/ffroliva/gflow-cli/blob/main/docs/ACCOUNT_SAFETY.md)；[原始实践帖，效果与成本说法未独立复现](https://x.com/binghe/status/2125240336704491613)。短链 `https://t.co/bpPS1b4aPE` 已通过真实 HTTP 重定向核验，终点为上述项目仓库。

【可信度/待核验点】仓库身份、非官方属性和维护者风险提示已核验；具体账号的风控概率、实际生成成本、成片质量及禁支出模式执行效果未实测。本条是本轮新核验的工具边界，不是 Google 今日新增禁令，也不声称使用它必然封号。
