# AI / Agent 战略雷达｜2026-11-08

结论：反复运行的 Agent 项目，值得优先保存可执行的成功路径，而不是先换更贵模型；一次性任务则不宜照搬重型封装。

## 1. ReproBridge：把成功运行交给下一个 Agent，而不只是留聊天记录

【事实】已核验 ReproBridge 论文原文。作者把复现产物标准化为修订后的代码、环境安装流程、实验启动脚本和复现指南，并让新会话中的 Agent 独立重跑，由另一个审计器检查执行证据。论文报告：四个受测模型的平均复现成功率从 76.4% 升至 92.6%，下游 API 开销平均下降 19.7%。这些是作者实验结果，不是我们本机实测，也不是通用编程成功率。

【影响】对股票研究/回测、Openwrite 评测和 Kanban 跨会话交接，新增证据支持一个具体优先级：把已经跑通的环境与命令变成可重用资产，比单纯增加说明文字更值得试验。它与此前“不要把失败经验无差别写成永久规则”的判断互补：保留可执行证据，而非堆叠告诫。论文研究的是 ML 实验复现，迁移到我们的项目仍是推断。

【动作】建议只挑一个确实反复运行的项目试点：在下一次成功执行时保存代码版本、依赖安装步骤、准确启动命令、输入/配置版本、原始日志和结果提取方法；随后让一个不接触原聊天的新会话重跑，用日志和产物验收。沿用 Hermes/Codex/Claude Code，不新增平台、不先更换模型。若任务只运行一次，不照搬完整构建流程。本次已完成原文核验与知识库归档，未修改项目代码或运行中的 Skills，也未开展本地效果测试。

【证据】[论文原文与实验边界](https://arxiv.org/html/2611.08452)；[论文入口](https://arxiv.org/abs/2611.08452)；[线索原帖](https://x.com/omarsar0/status/2119085975880212842)。重点参见第 2.2 节、方法部分与附录 E。

【可信度/待核验点】原文已核验，效果为作者报告，尚无本地独立验证。下游评估只纳入 1,463 个整理任务中符合参考结果条件的 1,029 个任务；不能外推为任意损坏仓库都能达到同样成功率。19.7% 只指下游 API 节省，不含构建、独立审计、GPU 和维护等完整成本。论文记录构建 API 成本为 5,026 美元；其 Sonnet 5 固定条件情景需要完整复用该批工作负载 13 轮才覆盖构建 API 成本。因此当前建议是轻量保存已有成功路径，不是为节省一次运行费用建设重型框架。
