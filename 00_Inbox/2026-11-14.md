# AI / Agent 战略雷达｜2026-11-14

常驻 Agent 优先补可靠交付与审批恢复；DeepSeek 新接口值得进入候选，但不能当作现有工具的无缝替代。

## 1. Anthropic 给出常驻 Agent 架构：可靠交付比多开 Bot 更重要

【事实】已核验 Anthropic 11 月 13 日发布的《Building always-on agents》。文章建议用持久化事件收件箱接收触发，每个收件箱同一时间只有一个活跃 worker，并按事件标识去重；需审批的工具调用可保存会话后结束本轮，待用户回复再恢复，不占住 worker。需要控制消息节奏或从错误中恢复时，再引入独立发件箱与投递器。记忆优先保存不能重新查询的信息，可查询的外部状态保存指针即可。这是架构指南，不是 Hermes 已上线这些能力的公告。

【影响】直接对应我们的定时雷达、长任务与 Kanban 协作：任务跑完不等于消息已送达，等待拍板不应卡死其他工作，多路事件也不应重复执行。同样重要的是，没必要为每条业务线再造一个 Bot，优先检查已有执行链能否恢复、去重和交接。

【动作】建议把下一轮自动化验收收敛为三项：同一事件重复到达不重复产生副作用；投递失败保留待发送状态，不能在确认送达前永久标记已通知；审批挂起后其他任务仍可执行，批准后能从检查点恢复。后三项为针对本地工作流的工程建议，不是官方已为我们实现的保证。本次已核验原文并归档为验收依据；未改动 Hermes、定时任务或权限配置。

【证据】[Anthropic 官方原文](https://claude.com/resources/articles/building-always-on-agents)。

【可信度/待核验点】原文架构与发布日期：高；本机是否存在对应缺陷：未审计，不下诊断。无需为采用这些原则迁移框架或更换模型。

## 2. DeepSeek 开放搜索、文件与语音接口：接入前先核对参数和费用边界

【事实】官方公告与 API 文档已确认：搜索、文件输入、URL 读取、内容安全、ASR 和 TTS 等能力可通过 API 使用；聊天能力指南指定 deepseek-flash，支持 Messages、Responses 与 Chat Completions。服务端负责搜索与链接读取。官方公告明确扩展能力在 token 费用之外另收工具使用费。文档还明确：启用指定内置工具、安全检查或标题功能时，一些请求参数会被忽略，例如 Responses 的 max_tool_calls、parallel_tool_calls 和 store；max_output_tokens 限制每次推理步骤的输出，而非整轮总输出。

【影响】股票研究驾驶舱的检索、文档输入可以多一个供应商候选，但协议兼容不等于行为兼容：不能沿用原先的参数假设来控制调用量、成本或数据处理。也不能据此宣称已经降低成本。现有本地语音链路没有因此必须替换的理由；小说生成也不能把启用扩展能力后的采样参数当作仍然生效。

【动作】建议只把它列入驾驶舱数据入口的候选，不直接迁移生产链路。接入门槛：用同一组公开文档核对引用是否可追溯、提取结果是否完整；对工具费用和整轮预算做客户端独立控制；敏感文件上传前核对服务条款与数据处理规则，不把 store 参数视为有效承诺。本次已合并官方与中文转述为同一事件，完成文档核验；未调用付费 API、上传文件、替换模型或进行性能测试。

【证据】[DeepSeek 官方公告及费用说明线程](https://x.com/deepseek_ai/status/2121247896918253875)；[官方接入指南与被忽略参数清单](https://api-docs.deepseek.com/guides/build_a_chatbot)。

【可信度/待核验点】公告、接口范围和参数限制：高；实际质量、延迟、总成本、账号可用性及本地客户端兼容性：未实测。官方演示不等于生产验收。
