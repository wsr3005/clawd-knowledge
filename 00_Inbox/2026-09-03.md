# AI / Agent 战略雷达｜2026-09-03

**一句话结论：** 今天真正值得改动作的不是追逐所有新模型，而是把 Claude 5.1 纳入实测、把桌面操作视为高风险执行面，并用“单主 Agent + Skills + 强 harness”收敛架构。

## 1. Claude Fable 5.1：Claude Code 的默认高档位需要重新做成本—质量实测

【事实】**已证实。** Anthropic 已发布 Claude Fable 5.1；Claude Code 默认使用 High effort。按 token 计费时，基础输入/输出价格仍为每百万 token 10/50 美元，缓存读取降至每百万 token 0.25 美元（下降 75%）。Anthropic 估算典型负载总成本较 Fable 5 低约 25%，高 Agent 化负载最多约低 45%；但官方也明确这些是估算，实际成本取决于工作负载。Fable 5.1 已在 Claude API、AWS、Google Cloud、Azure 等平台可用。

【影响】昱桥当前的 Claude Code 编排/子代理工作流会直接受到影响：缓存密集、长上下文任务可能明显降本，但 High effort 也可能增加推理与输出消耗，不能把“缓存降价”直接等同于“订阅额度更耐用”或“每任务必然更便宜”。个人 X 关于额度迅速耗尽、隐形水印、切模缓存失效等说法目前没有在官方发布中得到完整确认，不应据此下结论。

【动作】把 Fable 5.1 先定位为规划、架构、验收与长时任务的候选主模型；用同一组真实任务记录完成率、总 token、缓存命中、墙钟时间和返工次数，与 Opus/Fable 5 做按任务 A/B。默认从 Medium/High 开始，不使用 Max 作为日常默认；在拿到实际账单/usage 数据前，不宣布降本。

【证据】[Anthropic 官方发布](https://www.anthropic.com/claude-fable-and-mythos-5-1) · [AI HOT 聚合入口](https://aihot.virxact.com/items/cmtj04igz04xproel00pt2oju)（AI HOT 显示 13 个独立信源）

【可信度/待核验点】发布、官方价格、默认 effort 与可用性为高可信第一方信息；25%/45% 是 Anthropic 的工作负载估算，不是昱桥实际成本承诺。订阅额度消耗、跨模型缓存和不可见水印需等待官方文档或自行复现实测。

## 2. Claude Code / Cowork 可后台直接操作桌面，但安全边界不能沿用普通代码 Agent

【事实】**已证实。** Claude 的 computer use 已以 research preview 进入 Claude Desktop 内的 Cowork 与 Claude Code，当前面向 Pro/Max，支持 macOS 与 Windows。它可通过截图理解屏幕并点击、输入、打开应用；没有 sandbox 隔开 Claude 与桌面应用。系统采用逐应用授权和 blocklist，但 Anthropic 明确警告防护并不完美，且 Team/Enterprise 当前不可用；电脑必须保持唤醒且 Desktop 应用开启。

【影响】这把 Claude Code 从“仓库内执行器”扩展为“跨应用操作员”，适合本地模拟器、报表整理和无 API 的内部界面；同时把 prompt injection、误点击、跨应用数据泄露和不可逆操作风险放大。尤其不能让它碰交易、支付、合同、发布后台、密码管理器或含第三方隐私数据的应用。

【动作】只在隔离的 macOS 用户/测试环境中试用；默认 blocklist 银行、交易、密码、邮件主账号、云控制台和发布工具。首批只做可回滚任务，并保留人工确认点；能用 connector/API/CLI 时优先不用屏幕操作。继续维持“发布、花钱、不可逆动作必须人工明确批准”的硬门禁。

【证据】[Claude 官方公告（X）](https://x.com/claudeai/status/2095226833293685100) · [Anthropic Help Center：能力、权限与安全限制](https://support.claude.com/en/articles/14128542-computer-use-safety) · [AI HOT 聚合入口](https://aihot.virxact.com/items/cmtkh71ky017vrolly7trswyx)

【可信度/待核验点】能力范围与限制均经第一方核验，可信度高。官方 X 串曾称 macOS，当前 Help Center 已写明 macOS 与 Windows；以 Help Center 的更新说明为准。实际可靠性和 prompt-injection 抵抗能力仍需本机小范围测试。

## 3. Anthropic 给出生产 Agent 架构结论：默认单主 Agent + Skills，subagent 只做窄而自洽的任务

【事实】**已证实。** Anthropic 基于电商生产实践发布参考架构并开源 `anthropics/commerce-agents`：核心是一个模型运行标准 Agent loop，搭配 Skills、工具和 eval，而非前置 intent router 加一组领域 subagents。官方称在多个企业部署对比中，单 Agent + Skills 在质量上持续优于“大一统 prompt”和领域 subagent 方案，且通常成本、延迟更低；subagent 适合深度研究等窄而自洽、可返回压缩结果的任务。安全、法律、品牌等关键规则应放 system prompt，并由 harness 强制执行。

【影响】这直接校正 Hermes/OpenClaw/Claude Code 的编排方向：不要为了“多 Agent”而拆 Agent。共享上下文强、对话所有权连续的工作流应靠 Skills 模块化；只有能独立完成、上下文隔离收益明确的执行任务才下放 subagent。更重要的是，安全不能只写在提示词里，必须落到权限、暂存、审批和验证机制。

【动作】后续新增能力默认先写成 Skill，不新建常驻子 Agent；用三个问题作为拆分门槛：任务是否自洽、是否需要独立上下文、是否能用紧凑且可验证的结果返回。把发布/付款/删除等规则继续固化在 harness；把业务需求写成 eval，再换模型或改架构。

【证据】[Claude 官方工程指南](https://claude.com/blog/the-anatomy-of-effective-commerce-agents) · [官方参考实现](https://github.com/anthropics/commerce-agents) · [AI HOT 聚合入口](https://aihot.virxact.com/items/cmtkcffah018zrog0zokk6s30)（AI HOT 显示 2 个独立信源）

【可信度/待核验点】架构、代码与官方经验总结均为第一方，可信度高；“持续优于”来自 Anthropic 自有企业部署比较，未披露完整独立实验数据，应视为强实践信号而非普适定律。
