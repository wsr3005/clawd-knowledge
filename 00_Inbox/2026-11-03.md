# AI / Agent 战略雷达 · 2026-11-03

Claude 长会话新增传输提速能力，但不降 token 价格，也不能替代本地记录；先核兼容性，不为热点改现有工具栈。

## 1. Claude Message Threads 公测：省重传，不省 token 账单

【事实】已核验 Anthropic 官方文档和 ClaudeDevs 原帖：Messages API 的 Message Threads 已公测，首次发送完整对话，后续仅发送新增消息和上一回复 ID；Claude Code 已集成。官方报告在 50 万至 100 万 token 请求中，首 token 等待时间中位数降低约 35%；这是厂商观测，不是本机实测，也不能理解为任务总耗时下降 35%。定价和速率限制不变，提示词缓存仍需单独配置。线程在最后一次请求后 5 分钟过期，服务端最迟在最后使用后 1 小时删除；应用必须自行保存完整历史并支持重放。该功能不支持零数据保留（ZDR），也不适用于开启 HIPAA readiness 的组织。

【影响】对昱桥使用 Claude Code 的长编码会话，这是直接相关的等待时间优化，不是换模型或升级付费档的理由。对未来自建 Claude API 工作流，工具执行或人工审批间隔较长时可能触发全量重放，收益不能照搬。Hermes 当前默认使用 GPT-6 Astra，不会因 Claude API 新功能自动受益。系统提示词、工具或模型变动需要新建线程，接入前必须核查动态工具、上下文压缩及故障恢复的兼容性。涉及客户敏感材料时，不能把“仅存内存”误当作零数据保留。

【动作】已完成官方文档与官方账号交叉核验，明确保留完整历史、过期重放、提示词缓存独立配置三项接入约束。建议现有 Claude Code 工作流保持不变；若后续优化 Claude API 链路，先在非敏感长会话上验证首 token 等待、实际费用及过期恢复，再决定接入。不要为此改 Hermes 默认模型、购买新订阅或删除本地历史。本次未改运行配置，未调用付费 API。

【证据】[官方 Message Threads 文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)；[官方公测公告](https://x.com/ClaudeDevs/status/2117332449382510884)；[Claude Code 集成与厂商观测](https://x.com/ClaudeDevs/status/2117332451231956997)。

【可信度/待核验点】功能规则与官方集成声明可信度高；速度数字仅为厂商报告。本机 Claude Code 是否启用、实际收益，以及 Hermes 的 Claude 适配器是否支持，均未实测，不宣称已经提速。
