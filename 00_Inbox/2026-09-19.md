# AI / Agent 战略雷达 · 2026-09-19

一句话结论：跨工具项目规则开始收敛，但别急着删 CLAUDE.md；新披露的账号接管链提醒我们，连接器权限就是事故的扩散边界。

## 1. Claude Code 支持 AGENTS.md：规则可共用，迁移仍有前提

【事实】已核验 Claude Code 团队成员 Thariq 的第一方公告：从 2.1.277 开始，文件夹没有 CLAUDE.md 时会检查并使用 AGENTS.md，可通过 /config 切换该行为。不是两个文件自动合并，也不是宣布支持 .agents/skills。本次取得的官方主分支更新日志顶部仍为 2.1.274，与公告存在可见版本差异，不能据此认定本机已经支持。

【影响】对 Hermes、Codex、Claude Code 协同开发，判断：通用仓库约束有机会只维护一份，减少测试命令、修改范围和验收口径漂移；但既有 CLAUDE.md 可能让 AGENTS.md 不走公告所述回退路径。项目指令统一不等于 Skills 目录、权限或模型配置统一。

【动作】建议先保留现有文件；下一次获批维护时，用隔离目录验证“仅 AGENTS.md”“两个文件并存”及配置开关，再决定迁移共用规则。已采取：合并中文转述与同事件讨论，回查第一方原帖，排除把文件名写成 AGENT.md、把开关解读为“只支持 AGENTS.md”的未证实细节；未升级软件或修改项目规则。

【证据】[Thariq 第一方原帖](https://x.com/trq212/status/2101009392611278961)；[官方更新日志](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)。

【可信度/待核验点】公告内容已证实；本机版本、实际加载行为及配置范围尚未实测，公告与日志差异未解决。不宣称已经完成规则统一。

## 2. OpenAI 账号接管复盘：连接器会放大身份系统漏洞

【事实】已核验 Hacktron 研究团队原文：团队称在此前的测试中，将论坛图像解码漏洞与 OpenAI SSO 配置问题串联，接管员工 ChatGPT 账号，并通过其 Codex 在内部仓库创建验证用 PR；原文称 OpenAI 侧问题已修复。Discourse 官方安全公告独立确认：libheif 漏洞可经图像上传导致远程代码执行，修复涉及更新容器镜像，并加入图像处理沙箱。账号接管完整链条及 OpenAI 修复状态依据研究方披露，本次没有取得 OpenAI 独立公告；不能把潜在的 Slack、邮件访问说成已经发生的数据窃取。

【影响】对我们的 Codex 仓库接入和自动化基础设施，判断：低敏感入口的失陷可能经身份与连接器放大成高权限操作；不能因为 Agent 本身表现可靠，就授予整个 GitHub 组织或生产系统写权限。器械图像识别项目若接收外部图片，也应把解码组件与隔离列入交付安全检查，但目前没有证据证明该项目使用了受影响组件。

【动作】建议下一次权限审查优先核对 Codex 的仓库授权范围，研究任务以只读为先，写权限只覆盖必要仓库，交易凭证与普通开发环境分开。若图像服务使用相关解码库，再按发行版安全公告核验补丁与沙箱，不能只比较版本号。已采取：交叉核验研究复盘与维护方公告，将本事件与此前“模型交接摘要失准”分开；未撤销连接器、修改权限或运行攻击测试。

【证据】[Hacktron 原始复盘](https://www.hacktron.ai/blog/hacking-openai)；[Discourse 官方安全公告](https://github.com/discourse/discourse/security/advisories/GHSA-vhm9-85gw-x335)。聚合线索署名：[AI HOT](https://aihot.news/items/cmu6idvti04i9ro0fktczvi9g)。

【可信度/待核验点】图像上传漏洞及维护方修复指引已证实；账号接管和 OpenAI 修复情况为研究方一手陈述，未独立复现。本机、账号及客户项目是否受影响未核验，没有证据表明昱桥账号被入侵，不据此要求紧急停用 Codex。
