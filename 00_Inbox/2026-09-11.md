# AI / Agent 战略雷达｜2026-09-11

**一句话结论：** 优先防范 DeepSeek 模型别名换底座；云端 Agent 编排已有官方托管选项，Hermes 则补强了人工接管能力，不必因此迁移现有工具栈。

## 1. DeepSeek 不只是发布新模型：旧别名正在换底座

【事实】**第一方公告已核验，接口未实测：** DeepSeek 宣布 V4.1-Flash 已在 API 上线并支持原生多模态，推荐模型名为 `deepseek-flash`；`deepseek-v4-flash` 和 `deepseek-v4-flash-vision-exp` 暂时转向 V4.1-Flash。官方另宣布自 2026-09-14 04:00 UTC 起，所有 `deepseek-v4-pro` 请求也将转向 V4.1-Flash，并按后者费率计费，持续至 V4.1-Pro 发布。本次抓取的官方更新日志仍显示较早内容，因此迁移信息以已读取的官方 X 完整公告为依据，不据聚合摘要补写价格或跑分。

【影响】如果小说评测或研究自动化仍使用这些别名，即使配置未改，实验底座也可能改变；历史质量和成本对比不能继续当成同模型复测。这是条件性风险，不代表已确认昱桥当前项目正在调用这些别名。新视觉能力可以成为图文证据抽取的候选，但不构成替换默认 Astra 的理由。

【动作】建议把模型别名核对作为下一次 DeepSeek 批处理的前置检查；记录供应商、请求模型名、调用时间与返回模型字段（如提供），并保留供应商迁移公告，不能把返回别名视为固定权重证明。重新比较同一组小说/证据抽取样本的合格率与总成本后，再决定是否改配置。**已采取：** 合并 AI HOT、官方与个人 X 的同事件报道，追到官方迁移公告；未切换模型、未发起付费测试。

【证据】[DeepSeek 官方迁移公告](https://x.com/deepseek_ai/status/2097930620680941732)；[官方发布主帖](https://x.com/deepseek_ai/status/2097930608790167907)；[官方更新日志](https://api-docs.deepseek.com/zh-cn/updates)。聚合线索署名：[AI HOT](https://aihot.news/items/cmtv48yni0oq5rorpf4o74549)。

【可信度/待核验点】迁移安排属于已核验的官方声明；实际路由、具体价格、昱桥项目暴露与新模型任务表现待核验。未采纳第三方“同等效果低至某个倍数成本”的宣传。

## 2. OpenAI Agents API 公测：编排可托管，业务与权限仍要自己管

【事实】**官网已核验：** OpenAI 于 9 月 10 日推出面向所有开发者的 Agents API 公测，由 OpenAI 运行和维护 Codex 的 Agent 执行框架，提供上下文自动压缩、工具搜索、程序化工具调用及子 Agent 协作。执行环境可选 OpenAI 托管沙箱、自有基础设施或合作方沙箱。官方称 Agents API 本身不额外收费，使用的 token 和工具仍计费；这不是免费运行承诺。

【影响】对投资驾驶舱内嵌 AI 和商业化垂直 Agent，新增了“采购通用编排、自己做数据与业务流程”的选项，可减少重复建设。但把代码放在自有沙箱，不等于模型调用与编排也留在本地；客户资料、凭证和数据出境边界仍需单独审查。它是后台运行选项，不是需要增加一个日常聊天工具。

【动作】建议暂不迁移 Hermes/Codex/Claude Code 主栈；新建面向客户的云端任务时，将该 API 与现有方案放在同一验收表里，比较中断恢复、证据留存、人工审批、总成本与退出迁移成本。先核对数据条款和沙箱收费，再考虑获批后的非敏感小样本测试。**已采取：** 核验官网功能、公测范围与收费措辞；未创建云端会话、未上传客户数据、未消费额度。

【证据】[OpenAI 官网：Introducing the Agents API](https://openai.com/index/introducing-the-agents-api)；[官方开发者公告](https://x.com/OpenAIDevs/status/2098130570048045453)。

【可信度/待核验点】产品与公测说明可信度高；生产稳定性、账户实际可用性、沙箱及完整工作流费用未实测，不能宣称已比现有方案省钱。

## 3. Hermes 子 Agent 可实时观察、纠偏和停止：监督增强，不等于自动安全

【事实】**第一方公告已核验：** Nous Research 宣布 Hermes Agent 可实时显示子 Agent 的详细活动，并支持在 CLI 和桌面应用中手动引导、停止。官方委派文档同时明确：子 Agent 从独立上下文启动；进程消失后不能据此保证子任务恢复，完成结果的持久化也不等于运行过程可续跑。

【影响】在有人监督的工程与研究任务里，能更早发现跑偏并接管，不必等最后一份摘要。但这不能替代无人值守 cron 的预算、权限和隔离，也不能用来取消小说生产现有的 Kanban + profiles 分工。

【动作】建议把“活动可见、纠偏有效、停止后不继续产生副作用”列为下一次 Hermes 升级的验收项；不为尝鲜直接更新生产环境。**已采取：** 核验官方公告与文档，将人工接管和持久化执行明确区分；本次没有升级 Hermes、启动子 Agent 或修改其他 profile。

【证据】[Nous Research 官方公告](https://x.com/NousResearch/status/2098071687145365632)；[Hermes 权威文档：Subagent Delegation](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation)。

【可信度/待核验点】官方能力声明可信度高；本机安装版本是否包含更新、具体控制入口及停止效果未实测。公告的 CLI/桌面范围不外推至 Telegram。
