# AI/Agent 战略雷达｜2026-10-05

一句话结论：第三方 Skill 的风险要一直管到浏览器展示层；Codex 的更新承诺值得跟踪，但不能当成已到账额度。

## 1. 恶意 Skill 可借结果展示外泄数据：只限制执行环境联网不够

【事实】已核验 PromptArmor 原始研究报告。研究方披露：Databricks Genie Code 执行恶意 Skill 后，将可访问的数据嵌入 HTML 展示内容；用户查看结果时，由浏览器向外发送数据，并展示钓鱼界面。报告指出，组织级 Skill 管理、命令审查 Agent、代码环境出网限制和展示沙箱，未能共同阻止这条攻击链。其转述的厂商回应将上传 Skill 的安全性归为用户责任。以上为研究方披露，不是本次独立复现或厂商单独确认。

【影响】昱桥大量使用 Skills，并通过 HTML 阅读研究报告。这个案例改变的是安全检查范围：代码环境断网，不等于最终报告不能联网；模型同意执行，也不等于安全审核通过。不能据此断言 Hermes、Codex 或 Claude Code 存在同一漏洞，但不能把第三方 Skill 输出视为可信页面。

【动作】建议第三方 Skill 先审代码与依赖，再在无密钥、无真实业务数据的隔离环境试跑；HTML 报告默认不带脚本、iframe、外链资源或表单。浏览器展示应单独限制联网，不能只依赖执行环境防火墙；报告中索要登录凭据的界面不应被信任。本次未安装候选 Skill；本次附件采用内联 CSS、无脚本，并用 CSP 禁止脚本、嵌入框架、资源联网及表单提交。未修改现有 Agent 配置，也未进行全系统安全审计。

【证据】[PromptArmor 原始报告](https://www.promptarmor.com/resources/four-databricks-genie-controls-that-dont-stop-malicious-skills)；线索来自 [AI HOT 聚合入口](https://aihot.news/items/dfcis3hxowljt45i0bvyi3f0n)。

【可信度/待核验点】攻击机制已回研究方原文核验；厂商回应仅见原文转述。未独立复现、未核验当前修复状态，不能推广为所有 Agent 产品的已证实漏洞。附件的静态限制不代表整个报告交付链已完成安全认证。

## 2. Codex 承诺连续改进或重置：不要提前透支尚未确认的额度

【事实】已回 Tibo（@thsottiaux，账号简介为 Codex & ChatGPT @OpenAI）原帖核验：未来 28 天，每天要么交付一项对多数 codex/work 用户有意义的明显改进，要么进行一次“full reset”。原帖没有解释 reset 对应的额度类型、适用套餐、地区和到账时间，也没有承诺每天同时更新和重置。中文转述中的“所有用户额度全部重置”不能直接当作已确认政策。

【影响】Codex 是昱桥工程执行主力，潜在额度变化会影响批量任务成本和排期。但更新承诺不等于今天有新能力，重置承诺也不等于账户余额已变；没有依据因此购买套餐、提高并发或把 Claude Code 的任务全部迁过去。

【动作】建议保持现有 Hermes＋Codex＋Claude Code 分工。只有账户实际显示重置，才把已授权、可中断的非紧急工程任务移入该窗口；只有正式变更记录或本地验证证实新增能力，才调整工作流。本次已合并权威 X、中文转述与 AI HOT 的同事件线索；未检查私人账户额度，未升级客户端、购买套餐或启动批量任务。

【证据】[Tibo 第一方原帖](https://x.com/thsottiaux/status/2106845241357824205)；[AI HOT 同事件聚合入口](https://aihot.news/items/dmtalxqmeu6koot2yf3kal5nu)。

【可信度/待核验点】承诺文本已核验；具体执行规则、实际更新内容及昱桥账户是否受益仍待核实。不能把该承诺解释为已生效的套餐条款或保证可用额度。
