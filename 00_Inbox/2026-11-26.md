## 1. Claude 把技能与长任务接入 MCP：先验收无人值守边界，别急着替换 Kanban

【事实】已核验 Anthropic 原始公告：Skills over MCP 在 Claude／Claude Code 进入公测，服务器可一起发布工具和操作技能，技能按需加载并随服务器更新；Pro、Max、Ultra 默认开启，Team 需管理员启用，Enterprise 尚待开放。Tasks 与 Elicitation 已面向上述个人付费套餐正式开放，团队／企业逐步推出。Tasks 让支持它的服务器在后台运行长任务、再交回结果；Elicitation 是中途向用户索取输入的机制，可用于费用或删除确认，并不是给所有敏感操作自动加锁。File Uploads 仍是即将推出，不计入当前可用能力。

【事实】执行边界比发布标题重要。Claude Code 文档明确：远程 MCP 任务可在退出后继续，并通过恢复同一会话继续跟踪；本地 stdio 服务器进程会随 Claude Code 退出，不能一概承诺续跑。普通一次性 `claude -p` 调用不自动获得 MCP Tasks；受支持的非交互模式还需要相应输入方式、开关及协议条件。非交互 MCP 任务一旦要求用户输入，Claude Code 会向服务器请求取消；取消请求不保证服务器已经停止。Hermes 官方文档另明确：cron 等无人值守会话会拒绝 Elicitation，URL 模式尚不支持。这些是文档边界，不是本机端到端实测结论。

【影响】对投资研究长任务、文档处理与小说生产，新增了一条“工具和操作说明一起交付 → 后台执行 → 返回结果”的标准化路径，有望减少技能与工具不同步、长调用阻塞的问题；这属于适配价值判断，尚无本机收益数据。它不能替代 Kanban 的任务状态、失败处理和交付验收。远程技能会更新，也意味着接入审核必须覆盖指令与附带文件，不能只审一次工具名。MCP 技能规范要求把内容视为不可信输入，持久批准绑定文件清单与摘要，内容变化后重新批准；规范要求不等于当前客户端已全部执行到位。

【动作】已完成公告、协议安全要求、Claude Code 执行限制及 Hermes 文档交叉核验；本机只读检查返回 Claude Code `2.1.331`，不据版本号认定账号功能已开放。建议先列入现有自动化基础设施评测，不新建编排平台、不替换 Kanban：用不触发付费调用的公开资料处理任务，在隔离环境验证断开后恢复、结果可取回、重复提交不重复写入，以及遇到确认时停止并报告。接入远程技能前核验来源与内容变更；花钱、发布、删除仍须昱桥明确授权。本次未升级客户端、安装 MCP、修改配置或运行付费评测。
