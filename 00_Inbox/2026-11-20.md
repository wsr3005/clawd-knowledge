# AI / Agent 战略雷达｜2026-11-20

升级 GPT-6.2 前先核验上下文与计费适配；Hermes 企业化让“安装 Agent”更难成为卖点，商业价值应落在可验收的业务流程。

## 1. GPT-6.2：不只是缓存故障，官方明确了新的指令计费与推理保留边界

【事实】已核验 OpenAI 官方公告及文档：GPT-6.2 的 Responses API 将推理条目与它之前的对话历史绑定，修改旧消息可能导致后续推理条目被移除，增加重算、延迟和成本，也可能损害输出质量。当前缓存文档还明确：从 GPT-6.2 起，顶层 `instructions` 被追加在 `input` 之后，每次均按非缓存输入计费，即使内容完全相同；可复用指令应放在 `input` 开头的 `developer` 消息中。社区 issue 将这一现象称为缓存回归，但不能据此断言它仍是等待修复的计费 bug。另须区分：官方压缩机制保留后续推理，不等同于自行改写历史。

【影响】这是对前两天“新模型降价、后台折扣”的重要补充：标价更低，不代表长任务实际更省。若接入层反复将大段固定规则放进顶层 `instructions`，或事后截短已发送的工具结果，收益可能被重复计费和推理重算抵消。对 Hermes／Codex 长任务、小说校验和研究流水线，应先查请求构造，再决定是否升级；这不是当前默认模型或本机已经出故障的证明。

【动作】已将官方规则与社区故障报告交叉核对，纠正“只等缓存 bug 修复”的判断。建议把接入验收固定为：长期规则置于起始 `developer` 消息，临时指令与后续变化追加在末尾；长工具结果在首次发送前裁剪；需要压缩时区分官方机制与自建摘要。下一次获准评测同时检查 `cached_tokens`、`input_transformations` 中的 `prefix_mismatch`、任务质量及实际用量；缓存命中本身不能证明推理得以复用。未经兼容性验证，不直接搬动运行中提示词、不升级框架或切换默认模型。本次未调用付费推理。

【证据】[OpenAI 官方发布](https://x.com/OpenAIDevs/status/2123566018866151579)；[官方新增诊断入口](https://x.com/OpenAIDevs/status/2123566052001136885)；[官方前缀与压缩规则](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged)；[官方缓存与 instructions 计费说明](https://developers.openai.com/api/docs/guides/prompt-caching#how-caching-works-earlier-models)；[社区原始问题报告，仅作现象线索](https://github.com/openai/codex/issues/62312)。

【可信度/待核验点】当前官方公告和网页规则：高；本机请求形态、SDK 支持、订阅扣额及实际节省：未实测。官方同页 Markdown 入口仍返回未包含 GPT-6.2 指令例外的文本，本次按两份相互印证的 HTML 文档表述；实施时仍须核对实际接口。社区的账单和额度推断不作为本机已发生损失的证据，也不宣称所有缓存问题均已解释或修复。

## 2. Hermes 进入 Teams／Azure：企业交付底座更完整，别把部署本身当护城河

【事实】已核验 Nous 官方公告：Hermes Enterprise 提供 Microsoft Teams 工作入口，任务在 Azure Container Apps 沙箱执行，支持部署到客户自有 Azure 租户；Collective Wisdom 让员工把有效做法沉淀为技能，经审核后分享给团队。产品页同时区分 Nous 托管的 Business 与客户控制基础设施上的 Enterprise，不能把普通团队套餐等同于私有部署。这是企业产品的能力声明，不是本机开源 Hermes 自动获得同等服务。

【影响】对昱桥的 AI 商业化，这是交付方式变化，不是再买一套工具的理由。我的判断：通用聊天入口、部署和技能共享正被平台打包，单卖“帮你装 Agent”更难形成差异；更值得卖的是特定业务流程、数据接入、权限边界和可验证结果。已有 Microsoft 环境的潜在客户多了一条候选交付路径，但不能据此认定现有甲方采用 Azure、愿意采购，或医疗数据合规已经解决。

【动作】已核对公告与产品页，并将其定位为企业客户需求出现时的交付备选，而非当前主栈迁移计划。遇到真实需求，先锁定一个可验收流程，再确认客户办公平台、数据流向、模型供应商、审计和费用；技能分享必须排除客户敏感信息。公告写“审核后分享”，产品页却概述为“自动共享”，因此审批开关、共享范围与隔离边界必须在试点前核实。本次未开通团队、部署 Azure、上传客户材料或付费；现有 Hermes＋Codex＋Claude Code 主栈不变。

【证据】[Nous 第一方公告](https://nousresearch.com/hermes-enterprise-in-microsoft-teams)；[Nous 官方发布帖](https://x.com/NousResearch/status/2123535954946257096)；[官方 Business／Enterprise 产品边界](https://portal.nousresearch.com/business)；[Hermes 官方文档入口](https://hermes-agent.nousresearch.com/docs)。

【可信度/待核验点】第一方公布的入口、部署选项及产品区分：高；定价、地域可用性、企业合同、具体审批机制和端到端数据驻留：未逐项核验。自有 Azure 租户不自动保证所有模型推理留在租户内，须独立确认模型调用与数据处理链路。商业差异化判断是分析，不是已验证的客户需求或收入；未采用厂商规模与性能宣传数字。
