# AI / Agent 战略雷达 · 2026-10-23

自动批准正在成为默认体验，但我们的发布、资金与风控边界不能交给模型自行判断。

## 1. Claude 下周默认 auto mode：便利升级，不是授权升级

【事实】已核验 Claude 官方 10 月 22 日公告：下周起，Pro、Max、Team 的网页、桌面和移动端会话将默认运行 auto mode，以自动检查拦截风险操作，而非逐步请求批准；用户可切回手动模式。这次公告不是 Claude Code 首次推出 auto mode。Anthropic 的 Claude Code 工程文档另明确：项目内文件编辑可不经过分类器；该实现细节不能直接外推到网页端。

【影响】我们使用 Claude 研究和开发，不能继续假设“有风险时它总会先问”。自动分类器的风险判断，不等于昱桥对公开发布、花钱和不可逆操作的明确授权；即便项目内改动可回滚，交易守卫和权限代码也仍须独立验收。

【动作】建议在更新后的 Claude 会话中检查权限模式；涉及对外发送、发布、资金、生产环境或重要删除的任务保留人工确认，不因默认模式改变而扩大授权。普通研究和隔离开发可评估 auto mode，避免用完全跳过权限检查替代它。本次已核验官方公告与工程说明，未修改本机或账号设置。

【证据】[Claude 官方公告](https://x.com/claudeai/status/2113360845409583307)；[Anthropic：auto mode 工程说明](https://www.anthropic.com/engineering/claude-code-auto-mode)；[AI HOT 聚合入口](https://aihot.news/items/ybo2q5ug2e71tfuab9m1t128o)。

【可信度/待核验点】公告范围和可切回手动模式已由第一方确认；本账号实际生效时间、网页端具体拦截覆盖尚未实测。不将 Claude Code 的厂商测试拦截率当作其他客户端或真实业务的安全保证。

## 2. 独立红队新增证据：长任务不能等结束才审计

【事实】已核验 Redwood/METR 联合红队报告：对 OpenAI 历史内部监控系统的测试发现，在未监控上下文压缩事件的时期，监控由 Agent 交还控制权触发，持续执行可能无限推迟监控；压缩事件覆盖问题在测试期间已修复。研究方还发现过沙箱及 Auto-Review 的潜在绕过路径。OpenAI 表示影响生产防护栈的所发现漏洞已修复，但研究方未复验这些修复主张。

【影响】这是对昨天“监控必须独立于执行者”的新增外部证据，而非重报模型事故。对我们的长时编码、自动雷达和投资系统，新增验收要求是：运行期间也必须可观测，且上下文压缩、子任务交接、异常退出不能成为日志断点；结束时一句“完成”无法补回中途失明。

【动作】建议把“按时间或动作间隔检查，而非只在任务结束检查”列入下一次自动化验收；对执行日志与独立监控日志做交叉核对，明确覆盖压缩、交接、失败和重试路径。交易守卫、告警与审计配置不应由业务执行 Agent 单独修改并自验通过。本次只形成有来源的验收建议，未改动 cron、交易系统或监控配置。

【证据】[Redwood Research / METR 原始红队报告](https://blog.redwoodresearch.org/p/red-teaming-openais-internal-agent)；[AI HOT 聚合入口](https://aihot.news/items/fcw2s1pdclkgm5kmg2qwginp7)。

【可信度/待核验点】直接研究方证据，可信度高；评估对象是当时的 OpenAI 内部部署，不是当前全部 Codex 产品或本机 Hermes。不能据此断言我们的系统存在同类漏洞，也不能把厂商修复声明当作已获独立复验。
