# AI / Agent 战略雷达 · 2026-11-09

一句话结论：优先补安全审查与记忆纠错，不因新品预告或长上下文热度更换现有工具栈。

## 1. Hermes 官方安全插件：值得试点，但不等于安全认证

【事实】已核验 Nous Research 官方公告：Security 插件会分析攻击面与信任边界，分派子代理审查代码，并检查候选问题的可利用路径；开启测试确认后，会在仓库临时副本中生成并运行复现。报告记录证据及被排除的发现，可导出 SARIF，支持聊天、CLI 和桌面 Security 页面入口。这是官方声明的能力，不是本机实测结果。

【影响】我们的投资驾驶舱、自动化脚本涉及外部输入、凭证和执行权限。它提供了一条把“AI 看代码说有风险”升级为“有路径、有复现、有排除记录”的审查路线；但临时副本不等于隔离运行环境，不能因此允许接触交易密钥或生产服务。

【动作】建议将投资驾驶舱作为首个试点：只用脱敏副本，在无生产凭证、无实盘权限的隔离环境中审查；人工复核可达路径与复现后再安排修复。本次已核验官方公告，未安装插件、未运行扫描、未修改项目。不要把无发现当作安全证明。

【证据】[Nous Research 官方公告](https://x.com/NousResearch/status/2119501958981857543)；[Hermes 官方文档入口](https://hermes-agent.nousresearch.com/docs)。

【可信度/待核验点】发布与官方描述已证实；本机版本兼容性、安装要求、模型成本、误报和漏报情况仍待实际试点。未取得插件详细文档，不推断其隔离保证。

## 2. Anthropic 记忆研究：回查原始记录，而不是继续堆规则

【事实】已核验 Anthropic 原文：其记忆架构区分原始会话记录、记忆笔记、wiki 等组织结构及每轮注入的上下文；“dreaming”通过离线回查记录纠正记忆、整理索引。研究也发现，在所测 CL-Bench 数据库任务中，限制模型“只记录失败”会削弱部分模型的记忆收益。作者明确指出：记忆会过时或写错，维护需要额外计算，持续核验全部记忆未必可行。

【影响】这给我们的小说 wiki、Hermes 经验记忆提供了更具体的维护方向：让规则能追溯到原始证据，比把上下文越塞越满更重要。它补充了此前对“复盘规则可能增加负担”的警告，但不证明这套方法在小说或投资任务中必然有效，也不意味着 Claude Code 已默认启用这些功能。

【动作】建议下一次知识库维护先小范围验证：选反复调用或易过时的规则，保留来源、适用环境与失效条件，回查原始会话；候选纠错先形成差异，不直接覆盖生产记忆。用真实任务对照检查回答是否更正确、检索是否更省事，再决定是否扩大。不要只存失败，也不要把未经检验的成功经验升级为永久规则。本次仅完成证据核验和归档，未改写运行中记忆。

【证据】[Anthropic：The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)。

【可信度/待核验点】研究方法与局限已由第一方原文核验；属于厂商研究，不是独立复现。在当前 Hermes / 小说 wiki 上的收益与成本尚未实测，不据此新增后台任务或切换模型。
