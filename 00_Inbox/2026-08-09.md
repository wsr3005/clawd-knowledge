# AI / Agent 战略雷达｜2026-08-09

**一句话结论：** Agent 工作流正在同时越过三道门槛：Claude Code 降低长任务的人为中断，多会话开始原生协同，而“低价模型先跑、测试失败再升级”已出现值得实测的成本证据；UI 项目则应把可版本化原型前置为实现门禁。

## 1. Claude Code：Auto mode 将成为默认，多会话可原生互发摘要

【事实】Anthropic 官方宣布：从 8 月 14 日起，Claude Code 的 Pro、Max、Team 新会话默认使用 Auto mode；已固定默认权限模式的配置不会被覆盖。Auto mode 的分类器开销不再计入上述套餐用量。Claude Code 同时新增跨会话消息：同机上的会话可通过 `ListAgents` / `SendMessage` 发送摘要、提问和回传结果，而不是共享完整历史或文件；官方称目前可在 macOS 和 Linux 使用。

【影响】这不是一个小功能更新，而是 Claude Code 从“人盯着逐次授权的单会话工具”转向“可长跑、可横向协调的执行网络”。对昱桥的多 Agent/Kanban 流程，手工复制上下文和共享 Markdown 状态文件不再是唯一同步方式；同时，默认自动执行意味着安全责任会从频繁点击确认转移到仓库权限、命令策略、沙箱和验收门禁。

【动作】在 8 月 14 日前检查 Claude Code 的 `defaultMode`：高风险仓库固定现有模式，隔离的实验仓库再启用 Auto mode。选一个双 worktree 任务试跑跨会话消息，比较其与共享状态文件在上下文丢失、冲突和人工干预次数上的差异；未验证前不要一次性迁移全部编排。

【证据】[Anthropic：Auto mode 公告](https://claude.com/blog/auto-mode-default-in-claude-code)；[Claude Code：跨会话消息文档](https://code.claude.com/docs/en/cross-session-messaging)；[ClaudeDevs 官方发布](https://x.com/ClaudeDevs/status/2085817074816070014)；[AI HOT 聚合入口](https://aihot.virxact.com/items/cmsjaksyd04hlroo5hdy2qd4i)

【可信度/待核验点】高：发布日期、适用套餐、配置例外和消息边界均来自 Anthropic 官方来源。实际安全性和多会话收益仍需在昱桥自己的仓库、命令集与权限边界上验证。

## 2. 代码 Agent 的降本路线：低价模型先跑，测试失败再升级

【事实】Together AI 在自家 DeepSWE 实验中，对 113 个真实开源仓库任务分别运行 DeepSeek‑V4 Flash 0731 与 GPT‑5.6 Luna（每任务四次尝试）。其报告称，单次 Luna 的通过率和速度更高；但以 DeepSeek 先执行、测试套件拒绝后再升级到 Luna 的级联方案，在该次实验中完成 78.9% 的任务，平均每任务 0.385 美元；Luna 单跑为 67.2%、0.61 美元。即该级联在这组任务上完成更多任务，平均任务成本低约 37%。

【影响】真正值得拿走的不是“某模型更强”，而是路由原则：**可自动验证的任务，不应默认把最贵模型当第一跳。** 这可直接改变 Codex/Hermes 批量修复、重构和测试任务的模型成本结构；但它依赖可靠测试作为路由器，没有测试的任务不能照搬。

【动作】在一个测试覆盖较好的真实仓库做小规模 A/B：低价模型先跑，完整测试失败后升级强模型；记录成功率、总成本、墙钟时间和回归数。只有自有数据复现“更便宜且不降质量”后，才把它写进默认 Agent 编排。JS 重任务暂不直接推广，因为该报告中 DeepSeek 的 JS 表现明显弱于 Luna。

【证据】[Together AI 原始实验报告](https://www.together.ai/blog/deepseek-v4-flash-0731-vs-gpt-5-6-luna-on-deepswe-cost-and-coding)；[Together AI 官方 X](https://x.com/togethercompute/status/2085886342265819458)

【可信度/待核验点】中：实验方法、样本量和明细由 Together AI 公开，但属于模型服务商自测，尚非独立复现；价格、延迟和结果只代表该运行环境，不能外推到昱桥的仓库。

## 3. UI 项目应把“原型先行”写进 Agent 规则，而不是靠临时提醒

【事实】宝玉公开其开发流程：先用 Claude Design 维护本地 UI 原型，把“新增/修改功能时先改原型、确认后再实现”固化进 `AGENTS.md` / `claude.md`；原型以 React 代码和结构化数据保存，可用 Git diff 追踪。其开源的 Baoyu Design Skill 确认可在 Claude Code、Codex 等本地 Agent 中生成并维护自包含 HTML 原型、线框图和界面稿，产物可直接进入仓库版本控制。

【影响】这解决的是 Agent 开发里最浪费钱的一类返工：需求、界面和实现同时漂移。把原型设为实现前的低成本门禁，能先暴露交互与信息架构问题，并给编码 Agent 一个可 diff 的明确目标；这对 PPT、视觉产品、内容工具和任何前端项目都比“一句话直接改代码”更稳。

【动作】新 UI 项目默认采用三段式门禁：`原型变更 → 人工确认 → 功能实现与视觉回归`，并在项目级 `AGENTS.md` 固化。先挑一个小功能试行；原型与实现不一致时阻止任务标记完成。第三方 Skill 安装前先审阅内容与脚本，不把社区仓库直接视为可信执行代码。

【证据】[宝玉原始实践帖](https://x.com/dotey/status/2086144247388905833)；[Baoyu Design Skill 源码仓库](https://github.com/JimLiu/baoyu-design)

【可信度/待核验点】中高：工作流来自作者一手实践，仓库能力与 MIT 许可可核验；“降低返工、保持一致”的收益仍属个案经验，需要用昱桥项目的返工次数和交付周期验证。
