# AI / Agent 战略雷达 · 2026-10-21

一句话结论：OpenAI 宣布可选 12 小时提示词缓存，值得评估跨小时自动化的输入成本，但不要把 API 优惠当成 Codex 订阅额度增加，也不要直接改生产配置。

## 1. OpenAI 延长提示词缓存：先核对接入与账单，再启用

【事实】已核验 OpenAI Developers 10 月 20 日官方公告：API 可选择 12 小时提示词缓存，使共享指令、工具和上下文在相隔数小时的请求中复用缓存输入价格。官方跟帖称可选“12h”、保留 30 分钟默认值，或在同一请求中混用不同保留时长，并明确提及额外成本。注意：本次读取的官方缓存指南没有检出“12h”或“12-hour”，其保留策略段仍列出 in_memory / 24h 等配置；不能据此拼凑新参数或断言所有模型均可用。

【影响】对昱桥而言，候选收益是定时雷达、重复资料处理等跨小时任务复用稳定指令和工具定义，减少重复输入开支；这是条件性收益，不是已实现节省。当前会话使用 openai-codex 接入，不能把面向 API 的公告直接外推为现有订阅更省额度。缓存也不是长期记忆，不代表旧上下文自动进入新请求；官方指南明确缓存输入仍计入每分钟 token 限额。

【动作】建议将此列入下一次自动化成本审查：先确认实际调用是否走支持该选项的 API、模型及账户是否支持，再对照缓存写入附加费用、命中输入与完整账单；共享稳定内容和动态任务内容分开处理，低复用任务不默认延长缓存。只有账单证明净节省且数据保留要求允许，才调整生产配置。本次已完成官方公告与文档交叉核验；未改模型或缓存配置、未发起付费测试。

【证据】[OpenAI Developers 官方公告及跟帖](https://x.com/OpenAIDevs/status/2112603916076781778)；[官方提示词缓存指南](https://developers.openai.com/api/docs/guides/prompt-caching)。

【可信度/待核验点】公告内容已证实；文档与公告的配置描述尚未对齐。新选项适用模型、请求字段、附加费率、数据保留政策，以及 Hermes / Codex 当前接入能否透传，均未在本次确认；不宣称已可在现有主栈直接启用或能够节省具体比例。
