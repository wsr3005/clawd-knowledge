# AI / Agent 战略雷达 · 2026-10-19

一句话结论：Harness² 提供了用执行证据改进 Agent 工作流的新参考，但其 Codex 路径关闭沙箱，不能直接接入我们的生产环境。

## 1. Harness²：值得借鉴改进流程，不照搬运行权限

【事实】已核验 google-research/harness2 第一方仓库：该框架保持模型权重不变，通过提出工作流修改、执行候选方案、比较执行证据再合成修改，并保存经验，优化提示词、工具指导、记忆和技能等组件；支持 Codex 执行器。README 明确警告：执行器网络访问不受限制，Codex 运行时关闭沙箱；项目并非 Google 官方支持的产品。仓库提供无需模型凭证的确定性本地演示，但它不等于真实模型效果验证。

【影响】对昱桥的 Skills、Kanban 与工程自动化，新增价值不是再装一个 Agent，而是把“失败后改提示词”变成“候选修改有执行证据、能与原流程对照”的方法。与此同时，自动修改组件叠加无沙箱执行，会扩大文件、凭证和网络暴露面；不能把研究框架的默认权限搬到股票系统或日常主机。研究自报的基准收益不证明我们的成功率提升，也不证明总成本降低。

【动作】建议将下一次已有工程任务的流程优化限定为：保留原流程作为基线，候选改动只涉及任务技能或工具指导，用相同任务及独立验收比较结果，同时记录耗时和调用成本，再决定是否采纳；生产安全规则不交给优化器自行修改。如要运行该框架，先使用无生产凭证、无主目录挂载、受限网络的隔离环境，并设置预算与停止条件。本次已完成第一方核验和风险归档；未安装框架、未关闭沙箱、未调用付费模型，尚未开展效果实测。

【证据】[第一方仓库与 Web access 警告](https://github.com/google-research/harness2#web-access)；[框架说明与演示入口](https://github.com/google-research/harness2)；发现线索：[MarkTechPost 原文](https://www.marktechpost.com/2026/10/18/google-harness2-recursive-agent-harnessing-framework/)；聚合来源署名：[AI HOT](https://aihot.news/items/dx71nlu9cfqru07lmiqaiqu9d)。

【可信度/待核验点】机制、Codex 支持及默认权限警告为第一方文档已核验；真实任务收益、总调用成本、隔离配置的有效性均未实测。README 的安装路径面向 Linux，不据此声称可直接在当前 macOS 上运行。今天不重复推送此前已归档的 DeepSeek 搜索接口、OpenCode Console 安全事件及 Claude Code 审查流程。
