## 1. Codex 大请求传输修复：先做版本与回归验收，别把卡顿全归因于模型

【事实】已核验 OpenAI 工程师 Charlie Marsh 的完整说明及官方代码变更：Codex 的 WebSocket 请求大小上限由 16 MB 提至 128 MB；此前超限请求可能先上传、失败重试，再退回 HTTP，后续请求还会重复上传大段内容。客户端修复包括发送前读取服务端公布的大小限制，以及对早期超限拒绝直接切换传输方式，避免无效重试。官方 Codex CLI 0.170.0 变更日志已列入这两项修复。本机只读执行 `codex --version` 返回 `codex-cli 0.144.4`，默认命令路径为 `/Users/wangyuqiao/.local/bin/codex`；不能把上游发布当作本机已生效。128 MB 是传输限制，不是模型上下文容量或免费额度。

【影响】对投资驾驶舱工程、长材料研究和小说工具链，若出现“大工具输出之后，后续轮次持续变慢”，新增了一个可检查的传输层原因，而不必先切模型、砍任务或归咎于推理能力。它与前日报告的前缀缓存／指令计费规则是不同问题：本次改善上传与重试，不证明 token 费用下降，也不证明当前本机卡顿就是它造成的。

【动作】已把官方公告、修复 PR、发行记录与本机 CLI 版本交叉核对，未执行升级。建议下次获准的工具维护把“Codex 客户端兼容升级＋长任务回归”列入范围：先确认 Kanban 实际调用的二进制及启动参数，再在隔离测试目录验证登录、任务续跑、工具调用和权限边界；如原有案例确实出现大请求卡顿，固定同一任务比较重试日志与耗时。验收前保留现有默认模型、运行中任务和备用入口，不因服务端放宽限制就放任工具输出膨胀。

【证据】[工程师原始公告](https://x.com/charliermarsh/status/2123849871480463669)；[完整因果说明：上传、重试与 HTTP 回退](https://x.com/charliermarsh/status/2123849880451821627)；[官方 PR：早期超限直接回退](https://github.com/openai/codex/pull/60840)；[官方 PR：读取服务端限制并在发送前检查](https://github.com/openai/codex/pull/60841)；[官方发行记录：Codex CLI 0.170.0](https://developers.openai.com/codex/changelog)。本机证据：本轮实际运行 `command -v codex` 与 `codex --version`。

【可信度/待核验点】上游公布的变更、已合并代码及本机默认 CLI 版本：高。Kanban 是否使用同一路径、当前账号／代理链路是否享受新上限、升级后的实际改善：待核验。本次未运行付费模型任务或性能对照；不引用工程师报告的加速倍数作为昱桥的预期收益。

## 2. 漫剧老李：可复用小说到分镜的规则，但它默认不生成图片和视频

【事实】已从个人实践帖回溯到作者主仓库、总控 Skill、素材规则及许可证。当前包覆盖小说改编、角色／场景／道具约束、分镜、视频提示词、质检和离线看板；核心交付是提示词及素材对应说明，图片默认由用户在外部平台生成。规则明确区分“纯文字”“只有图片编号”“图片已回传登记”：只有最后一种才可做图像级核验。当前总控规定的视频模型路线是 Seedance 2.5／2.0，并非通用视频模型适配器。仓库根目录与总控目录许可证均为 MIT，要求保留版权与许可声明。以上是本次新核验的能力边界，不是今天新发布。

【影响】它给 AI 小说增加的是“已有自有内容 → 可检查的分镜与素材说明”这一候选中间环节，有机会用于后续小说宣传片或改编小样；不是装上即可自动生产短剧，更不能因为文字机检通过就声称角色形象和成片连续性已验收。它也不能直接与昨日的 PixVerse 路线无缝拼接：分镜思想可借用，模型专用语法与参考图规则必须另做适配。MIT 授权覆盖软件与文档，不自动授予原著、音乐、肖像或生成平台输出的商用权利。

【动作】已完成来源与授权边界核对，删去无法独立落证的播放量、成功率及商业收益暗示。建议列入现有小说商业化战线的备选，不另开短剧项目，也不把整套技能直接装入主环境。出现实际宣传或改编需求时，优先用自有原稿做一个短场景的隔离对照：检查台词是否漏删、角色／道具是否连续、提示词是否对应真实素材；只有接上生成平台并看过成片后，才评价返工与成本。本次未安装 Skill、生成样片、开通平台或消耗积分。
