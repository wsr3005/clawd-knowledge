# AI / Agent 战略雷达｜2026-11-19

优先评估非实时任务的 API 降本；界面复用与 Skills 自改都出现新依据，但不值得据此迁移主栈或放开自动部署。

## 1. OpenAI 后台折扣：等待换成本，不是订阅额度上涨

【事实】已核验 OpenAI Developers 官方公告及后台模式文档：GPT-6.2 Astra、Sol 的延迟窗口已进入公开测试；选择 2h，模型 token 单价比 Standard 低 30%；选择 8h，低 40%。这是初次响应的目标完成窗口，不是整条多轮工作流的交付保证，也不是只打开 background 就自动打折。文档要求折扣请求使用 Standard 处理、关闭流式输出；符合条件的后续请求也可享受折扣。

【影响】小说批量校验、隔夜材料整理、非紧急代码审查可以进入成本对照；小时级政策信号、BTC 风控与交互式编程不应为了折扣排长队。它改变的是 API 计费选项，不能推定 Hermes 当前登录通道或 Codex 订阅自动受益；单价下降也不等于任务总成本同比下降。

【动作】已核对折扣、请求条件和多轮续接规则。建议先把可延迟任务与实时任务分开，在下一次获准的 API 小样评测中记录实际账单、完成时间、失败重试及成品质量。接入时显式设置 `service_tier=default`、`background=true`、`background_options.completion_window`，关闭流式输出；保存响应 ID，排队时查询原请求而非反复重提。敏感材料另查临时存储边界，`store=false` 不代表后台执行完全不落盘。本次未改接入、未调用付费推理。

【证据】[官方发布与适用模型](https://x.com/OpenAIDevs/status/2123188195202617408)；[官方折扣与续接说明](https://x.com/OpenAIDevs/status/2123188224847982655)；[后台模式文档：完成窗口与限制](http://developers.openai.com/api/docs/guides/background)。

【可信度/待核验点】公告、折扣及文档条件：高；账号可用性、SDK 支持及实际节省：未实测。本次不同文档入口返回了新旧两个版本，折扣已与官方公告交叉核对，实施时仍须核验实际请求接口。新窗口是目标时限，不作准点交付承诺；工具费用和重试成本不能按模型 token 折扣一并估算。

## 2. Astryx：让 Agent 查组件规范，先别迁移驾驶舱

【事实】已核验 Meta 的 Astryx 官方站、仓库、CLI 文档与 MIT 许可：它提供组件、主题、页面模板及机器可读的 CLI／JSON 接口，不只是界面参考图库。组件库要求 React 19 或更高版本，目前仍为 Beta；仓库明确图表包只有 canary 预发布、尚无稳定版。CLI 文档另提醒：未安装官方 CLI 时，不要运行无作用域的 `npx astryx`，它会解析到无关的 npm 包；官方包名是 `@astryxdesign/cli`。

【影响】对投资驾驶舱与客户工具界面，可借鉴的新路径是让 Codex／Claude Code 查询确定的组件 API、布局和主题，而不是反复要求它“照截图变漂亮”。但图表稳定性恰好关系到驾驶舱核心需求，不能因展示页好看就替换现有前端。MIT 允许在遵守许可条件下商用，不等于附带素材和第三方依赖都无需核查。

【动作】已把中文线索回溯到上游，并核对许可、依赖门槛和包名风险。建议下次已批准的界面任务先选定表格、详情页和筛选区的参考规范，固定样式后再编码；若评估接入，只做隔离原型，验收中文、键盘操作、窄屏、空数据和报错状态，图表另设稳定性门槛。不为这个库迁移技术栈，也不全局安装 CLI；本次未安装依赖或修改驾驶舱。

【证据】[Meta 官方站](https://astryx.atmeta.com/)；[上游仓库与 React／图表包边界](https://github.com/meta/astryx)；[CLI 文档与包名警告](https://astryx.atmeta.com/docs/cli)；[MIT 许可原文](https://github.com/meta/astryx/blob/main/LICENSE)。

【可信度/待核验点】文档与许可：高；本地兼容性、中文体验及减少返工的效果：待实测。此项是本轮发现的可用工具线索，不声称今天首次发布；不采信个人帖中的模型审美排名，也不将厂商展示当成本机验收。

## 3. Skills 自改出现正面实证，但不是放任自动进化

【事实】已核验 11 月 17 日提交的预印本《Do LLM Agents Still Need to Be Told How to Self-Improve?》的方法、结果与局限：研究冻结模型权重，明确给出改善游戏表现的目标，让模型在受限预算和沙箱内生成练习、观察另一实例的表现，并修改提示词与技能文件。部分较强模型在未见过的游戏测试中改善，学习出的文本也能迁移到其他游戏环境；较旧模型未普遍受益。作者同时报告持续修改的收益会趋于平台，过度贴合评测条件可能损害迁移。

【影响】它给“可验证的 Skills 自改”增加了正面证据，但不是模型自行训练权重，更不是没有目标也会无限变强。与此前 /retro 研究的负面结果并不矛盾：任务、学习过程和评测环境不同。对 Hermes／Codex／Claude Code，值得区分的是“实际练习并比较改前改后”，与“失败后不断追加永久规则”；游戏结果不能直接外推为小说质量或交易收益。

【动作】已将正面结果与失败边界一并归档。建议只在下一次获准的技能实验中尝试：冻结模型和测试入口，限定可修改文件与预算，保留原版本；练习集用于生成候选补丁，另用未参与优化的验收集及无关任务检查收益和副作用。只有净收益成立才按既有审批流程合入；不能让改写者自行降低验收标准。本次未启动自改循环、未修改运行中的 Skills 或其他 profile。

【证据】[论文摘要与提交历史](https://arxiv.org/abs/2611.23219)；[论文方法、结果与限制](https://arxiv.org/html/2611.23219v1)。

【可信度/待核验点】论文实验设置与作者报告：已核验；属于预印本结果，本次未独立复现。实验集中于受控游戏场景，行为关联不等于已证明因果，真实工程任务的净收益仍待验证。不把它写成 Hermes 已获得的新功能或本机已实现的能力提升。
