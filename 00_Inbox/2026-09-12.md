# AI / Agent 战略雷达｜2026-09-12

**一句话结论：** Astra 工作流优化应先精准加载指令、明确验收，而不是继续堆提示词；Pro 暂停订阅公告不等于现有账户停用。

## 1. Astra 官方新指南：精简技能触发，写清“做到什么才算完”

【事实】**官方原文已核验：** OpenAI 开发者博客发布针对 GPT-6 Astra 的技能与提示词调整指南：技能过多、描述过长时，Codex 会缩短描述，影响技能选择；建议收窄触发条件、多工作流技能用最小入口按需指向资料，并避免每次修改都强制读取整套项目文档。原文还指出 Astra 可能在初步实现后提前交回审阅，因此应把运行、检查和修复写入完成标准。这是官方经验指南，不是已验证的本机提效结果。

【影响】直接对应我们的 Hermes 默认 Astra、Codex 工程和小说 profile+model 评测。值得改变的是指令组织方式：保留领域知识和验收门，把无关步骤移出常驻上下文。不能把“新模型更可靠”的厂商判断当成撤掉发布、花钱、实盘交易授权或环境隔离的依据；也不能把 Codex 的技能描述缩短机制直接外推为 Hermes 的实现。

【动作】建议下一轮技能优化只挑一个高频工程工作流：触发描述写清适用与不适用任务，根文件只保留路由与硬边界，任务卡明确交付物、实际运行验证和停止条件；用同一组任务对比修改前后的误触发、提前停止、质量与用量，再决定推广。小说继续按 profile+model 分开评测，不全局套用。**已采取：** 核验官方全文并提炼上述验收方案；未修改技能、AGENTS.md 或授权规则，未声称已节省额度。

【证据】[OpenAI 原始指南：Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)；[官方发布帖](https://x.com/OpenAIDevs/status/2098480213244117065)。

【可信度/待核验点】官方建议可信度高；实际质量、成本改善及本地指令是否存在上述问题待实测。“精简”不是删掉测试要求，更不是取消安全边界。

## 2. Pro 暂停订阅：别误读为老账户停用，也别靠陌生中转救急

【事实】**第一方公告已核验：** Codex 负责人 @thsottiaux 宣布暂停 200 美元 Pro 档订阅，同时明确其他套餐和 API 仍可用，现有账户不受影响。原帖没有给出恢复时间；本次未进入结账页面验证当前购买状态，也不能据此保证取消后可以重新购买。

【影响】若计划通过临时升级该档扩充 Codex 用量，不能把这一选项当作确定可用的应急容量；但“下月老用户都不能续订”不受这条公告支持。也不能把 ChatGPT 订阅变更误判为 Hermes API 已停用。个人关注源中的超低价中转宣传，尚无足够证据证明模型真实性、数据处理或账号安全。

【动作】建议已有该档账户不要为排查额度而先取消再重订；先核对自身套餐、用量和官方通知。将非紧急任务排队，保住主战役额度，不因促销把客户材料、投资资料或凭证迁到未经核验的中转。**已采取：** 从中文转述追溯第一方完整原帖，纠正“暂停订阅=老账户失效”的误读；未变更账户、购买额度或接入中转。

【证据】[第一方完整公告：@thsottiaux](https://x.com/thsottiaux/status/2098113585683808624)。

【可信度/待核验点】公告措辞可信度高；当前购买入口、昱桥实际套餐和账户续费状态未核验。现有账户不受影响不等于额度无限或未来条款永不变化。
