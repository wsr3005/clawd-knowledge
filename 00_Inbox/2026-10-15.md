# AI / Agent 战略雷达 · 2026-10-15

一句话结论：Hermes 新连接器值得优先评估只读接入；Claude Code 的空闲压缩会改变长任务续接方式，关键证据不能只留在聊天里。

## 1. Hermes 连接器上线：优先评估只读接入，不扩大自动写入权限

【事实】已核验 Nous 官方转引的开发者原帖：Hermes 连接器已发布，支持多账户及别名、通过 Nous Portal 同步连接器和设置，并可按读取、写入、破坏性动作限制连接器。自带 MCP 同步、认证时选择工具访问权限被明确列为“即将推出”，不能当成现成功能。以上是发布方声明，不是本机集成实测。

【影响】对昱桥的研究、项目管理与自动化，价值不是工具数量，而是有机会减少自建接口和账户切换，并将只读采集与对外写入分开。权限分类并不自动等于每次发布都有人审批，不能替代现有的发布、花钱和破坏性操作授权边界。

【动作】已核验开发者完整公告、官方转引及 Hermes 官方文档入口。建议下一次确有外部服务接入需求时，先评估官方连接器能否替代自建脚本；先用只读范围验证账户隔离、授权撤销及错误账户防护，再讨论写入。此次未升级 Hermes、绑定账户、同步设置或修改权限。

【证据】[开发者原始公告](https://x.com/sidbing/status/2110466271880028192)；[Nous 官方转引](https://x.com/NousResearch/status/2110470076595835353)；[Hermes 官方文档](https://hermes-agent.nousresearch.com/docs)。

【可信度/待核验点】发布内容已核验；当前安装是否具备相同能力、目标服务支持范围、OAuth 授权粒度及实际费用尚未核验。“无需账户”的宣传不能解读为外部服务不需要认证或全部免费。

## 2. Claude Code 空闲压缩：省用量，但续接依赖摘要

【事实】已核验 Anthropic 开发者 Lydia Hallie 原帖及同线程说明：Claude Code 新增空闲压缩，在长会话的提示缓存即将过期前进行压缩，恢复时处理摘要而非完整上下文，以节约用量。原帖给出的关闭方式是在 settings.json 中设置 "idleCompaction": false；也可用 CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS 自定义阈值。本次不将发布声明解释为本机已经启用，也不承诺具体节省比例。

【影响】昱桥用 Claude Code 做政策产业链研究与质询，隔一段时间续接时，未落盘的原文限定、反证与待核验点可能不再完整进入上下文。这是摘要压缩的工作流风险推断，不是已经观测到本机丢失信息。小说长任务的设定与验收标准也不应只依赖聊天历史。

【动作】已将 AI HOT 与个人 X 的同一事件合并并核验第一方原文。建议研究暂停前把原始链接、关键引文、反证和未决事项写入项目文件；续接时先重读这些文件。暂不全局关闭压缩；只有依赖完整历史且无法可靠落盘的任务，再核对安装版本和设置作用范围后决定是否关闭。此次未修改 Claude Code 配置。

【证据】[开发者原帖：摘要续接与关闭配置](https://x.com/lydiahallie/status/2110484841926152622)；[同线程：空闲压缩机制](https://x.com/lydiahallie/status/2110484840256819380)。聚合线索与署名：[AI HOT](https://aihot.news/items/whbmvotra7659u98jmj00oegi)。

【可信度/待核验点】机制和配置名称已由第一方原文核验；本机版本支持情况、实际触发行为、摘要保真度与节省用量均未实测。不把压缩功能等同于可无损恢复的长期记忆。
