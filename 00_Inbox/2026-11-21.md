# AI / Agent 战略雷达｜2026-11-21

长任务先管上下文，研究验收必须跑反证；Space 下放 Plus，新增文档／PPT 协作入口，但客户数据不能直接搬进去。

## 1. Space 向 Plus 开放：协作入口更便宜，数据边界不能省

【事实】已核验 OpenAI 官方公告：ChatGPT Space 向 Plus 用户开放，可围绕页面、幻灯片和站点协作，并新增手机编辑。同期工程公告称 Codex Remote 可靠性改善，但没有给出可验证的改善幅度。需要特别注意：Space 官方文档说明，共享页面中的内容会被有权查看页面的人看到；即使自己关闭模型训练，合作者开启训练时，共享贡献仍可能通过其交互用于训练。这是既有数据规则，不是此次新增条款。

【影响】对客户汇报、PPT 和项目材料，新增的是现有订阅内的协作候选，不必为了这一入口直接升级更高套餐。更重要的是，“我关了训练”不等于“共享材料都不会用于训练”；原始文件的访问限制，也挡不住已被复制到共享页的摘要。它适合先验证脱敏材料的协作效率，不能直接替代本地知识库或客户资料的受控存储。

【动作】已合并产品负责人和官方账号的同批更新，并核对共享规则。建议现有账号出现入口后，仅用脱敏汇报验证手机改稿、多人编辑和最终交付格式；未通过中文排版与可编辑性验收前，保留现有 PPT Master 流程。涉及客户材料，先核对所有参与者的数据设置与页面权限，不能确认就不上传。Codex Remote 仅列为已有远程需求的复测候选，不因“更可靠”就撤掉现有备用通道。本次未升级客户端、上传资料或新建共享空间。

【证据】[ChatGPT 官方开放公告](https://x.com/ChatGPT/status/2123850912867471807)；[OpenAI 产品工程更新](https://x.com/ajambrosino/status/2123840812534452296)；[Space 官方入门、权限与数据规则](https://help.openai.com/en/articles/20001549-getting-started-with-space-in-chatgpt)。

【可信度/待核验点】官方发布与共享规则：高；账号是否已开放、具体额度、手机编辑体验及 Remote 改善：未实测。入门文档仍写旧套餐范围及“手机不可编辑”，与新公告未同步，因此按新公告确认发布，不承诺昱桥账号已经可用；幻灯片导出与本地编辑效果另验。

## 2. Harness 新研究：该优化的是上下文流转，不是照着公司架构堆 Agent

【事实】已核验《Language Model Harnesses Can Be Compositional Generalizers》论文正文及作者仓库。研究把长材料放在外部运行环境中，让主模型用程序选取内容、调用子任务、保存中间结果，而不是不断把全部历史塞回主上下文。作者报告的平均提升 26.9%，来自对模型进行合成数据微调后，在同一 RLM 框架中的比较，不是“原模型套个框架就白得提升”。递归实验中，仅添加递归提示反而降低表现，额外训练后才获得改善。

【影响】对 Hermes／Kanban 的长任务，新增证据支持把投入放在“每次调用看到什么、子任务返回什么”，而非先配齐研究员、经理、测试员等角色。投资材料和小说校验都容易积累大段原文；值得验证的是让主控保留决策所需信息，并能随时回查原始证据。这是从论文提出的本地工程假设，不是已经证明能提高选股收益或小说质量。

【动作】已将传播中的“定制框架优势”与论文实际训练条件分开归档。建议下一次获准的长任务实验固定模型与验收集，对照现有流程和“原文外置、按需读取、子任务返回结论＋证据位置＋未决项”的流程；同时检查遗漏、跨材料矛盾、耗时和实际用量。保留证据回查，不能用短摘要替代完整依据。不扩一套主栈、不训练模型、不直接改运行中的上下文策略；本次未复现实验。

【证据】[论文原文：方法、表 4–6 与训练条件](https://www.alphaxiv.org/abs/2611.harness-cg.pdf)；[作者发布与论文入口](https://x.com/a1zhang/status/2123774098241147225)；[实验代码与复现说明](https://github.com/alexzhang13/harness-cg)。

【可信度/待核验点】论文方法与作者报告：已核验，尚未独立复现。收益依赖任务、模型和训练；较少 token 不等于同幅降本或提速。不能把新论文与作者较早博客的实验范围混用，也不能把研究框架视作 Hermes 已具备的新功能。

## 3. AI 研究社区的反例：数字能对上日志，结论仍可能是假的

【事实】已核验《A Society of AI Scientists》论文的审稿案例与局限。作者报告：将重大审稿异议写成脚本并运行后，156 条异议中有 77 条推翻了对应的核心统计结论；这是异议级别统计，不是全部论文的错误率。另有代码检查发现，所谓自进化校验器直接调用标准答案，另一个实验把失败重试覆盖成正确答案。只核对论文数字与输出文件是否一致，拦不住这些实现错误。

【影响】这为我们已有“必须实测”的要求补上一个更硬的边界：跑过代码、有日志、再加几个 AI 审稿人，都不等于方法成立。对策略模拟／回测、模型与 Skills 评测，验收还必须检查实现是否偷看答案、混入未来信息，或把失败记录洗掉；这不是本机已经存在这些缺陷的诊断。

【动作】已把“数值可复现”和“方法有效”拆开归档。建议下一次获准的研究验收，让审查者从原始输入独立重算关键结论，把足以推翻结论的质疑落实成可运行检查，并保留失败、异常和退出记录；同时核对关键代码与文字方法是否一致。模拟 API 与测试桩可用于界面场景测试，但截图必须标明模拟数据，不能充当真实数据接入成功的证据。本次未修改研究或交易系统，也未把 AI 审稿分数当作人类专家认可。

【证据】[论文原文：§4.4、§5.3、§7.1](https://www.alphaxiv.org/abs/2611.society-ai-scientists.pdf)；[作者摘要与论文入口](https://www.alphaxiv.org/abs/2611.society-ai-scientists)；[中文实践线索](https://x.com/dotey/status/2123671858541187164)。

【可信度/待核验点】案例、统计口径与研究局限：已核验原文，未独立复跑。研究为非随机观察，部分审计也由 Agent 完成；禁止人工代写等约束依赖参与者申报。其与人类论文的比较由模型阅读文本打分，不能推出“AI 科研已超过人类”。
