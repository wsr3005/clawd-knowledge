# AI / Agent 战略雷达 · 2026-11-04

自我复盘不等于能力提升：先给 Skills 变更设验证门，再考虑用共享代码图谱减少重复摸索，不为热度更换工具栈。

## 1. /retro 实证研究：规则越写越多，不保证任务做得更好

【事实】已核验论文原文：研究让 Claude Code 在 30 个 SWE-bench Verified 问题后复盘，收集 125 条建议；在原配置确实遇到目标问题的 7 个有效评估中，2 项改动消除了目标动作、1 项降低发生次数、4 项没有降低。研究没有发现一致的任务成功率改善，部分改动在无关任务上增加了检查工作。这里衡量的是特定动作是否重复，不等于这些动作本来就不必要，也不是“自我进化成功率”的通用测量。

【影响】直接约束 Hermes/Codex/Claude Code 的 Skills、项目说明和经验记忆建设：把一次失败写成永久规则，可能让其他项目背上无关检查。股票引擎和小说生产需要的是可复现的改善，而不是越来越厚的操作手册。

【动作】建议把复盘产物先当候选补丁：记录触发案例、适用仓库与环境；用原配置和改后配置跑后续任务，并补一个无关任务检查副作用；同时看成功率、耗时和重复动作，无收益则撤回。优先保留稳定的测试入口，环境相关的失败清单必须标明版本和失效条件，不能成为跳过测试的理由。本次已核验论文并归档判断，未修改任何运行中的 Skills 或记忆。

【证据】[论文原文：How Do Coding-Agent Harnesses Self-Evolve?](https://arxiv.org/html/2610.34938)；[作者公开实验材料](https://doi.org/10.5281/zenodo.23653700)（链接来自论文，材料未另行复跑）。

【可信度/待核验点】论文结果已核验；样本仅涉及一种 Agent、一版 /retro 和环境类问题，且部分任务经过定向选择，不能推广成所有自我改进无效。对昱桥项目的收益与成本仍待对照实测。

## 2. Understand-Anything：共享代码图谱值得小范围试验，不是免回归测试的护身符

【事实】已核验上游仓库 README：项目面向 Claude Code、Codex 等工具，结合 Tree-sitter 结构提取与模型语义标注，生成可共享的 `.ua/knowledge-graph.json`；提供差异影响分析，支持增量更新和可选提交后更新。官方明确提醒首次全库分析可能消耗大量 token。现有图谱的本地只读浏览可以不调用模型，但这不代表生成、维护或提问都没有成本。

【影响】对股票引擎与 Openwrite 的跨会话开发，它可能提供可复用的结构索引，减少每个窗口重新定位代码；这只是可验证的工程假设。静态结构不代表完整运行时调用关系，模型语义也可能出错，因此不能据此认定修改无风险。

【动作】建议仅列入工具候选，不全局安装、不自动挂提交钩子。若安排试验，先在单个非敏感子目录比较定位耗时、上下文消耗、依赖漏报与维护成本；图谱标注对应提交，过期时退回源码核查。只有净收益成立才接入 Kanban 编码流程，仍保留测试。本次已完成上游文档核验，未安装或调用付费模型。

【证据】[上游仓库与 README](https://github.com/Egonex-AI/Understand-Anything)；[中文实践线索](https://x.com/servasyy_ai/status/2117580007967264842)。

【可信度/待核验点】功能与成本警告已由上游文档确认，尚未本机实测；B-provisional 中文源关于节省成本和拦截回归的效果说法待核实，不采用其效果承诺。本条是本次发现的工作流候选，不声称这些功能今天才发布。
