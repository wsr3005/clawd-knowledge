# AI / Agent 战略雷达 · 2026-11-02

今天值得带走的不是再造视频网站，而是把批量情报处理拆成“规则缩池 → 模型判断 → 原始证据可回查”，不要让大模型通读所有原料。

## 1. HackerTube 的关键不是一键造站，而是先筛数据再调用模型

【事实】已核验 Karpathy 的项目原帖及本人补充：他使用 Claude Code 制作 HackerTube；处理流程先通过 URL、正则和垃圾内容过滤缩小数据范围，只把剩余内容交给 Sonnet 的 Claude Code 工作流。他还表示，视频下保留推荐评论，并提供评论分析数据供他人制作自己的版本。这是作者公开描述的实现流程，不是本次独立复现；不把开发速度、处理规模或推荐效果当作已测指标。

【影响】对昱桥的 AI 雷达和投资事件采集，值得借鉴的是成本与证据结构，而不是新增工具栈：确定性的清洗去重交给规则，语义判断交给模型，最终结论保留来源。投资场景不能直接照搬“反复被推荐即重要”的排序——低热度的一手政策可能比热门评论更有决策价值。这是适配推断，不是 HackerTube 已证明的投资效果。

【动作】建议下一轮采集链优化优先检验现有预筛是否误杀低热度一手资料，而非扩大模型通读量：为政策原文、监管公告和官方安全通告保留直通核验路径；抽查被过滤内容，比较漏报情况及实际调用消耗，再决定是否改规则。已完成原帖交叉核验，并剔除此前已报告的 Claude Ultra 与 OpenAI 额度旧闻。本次未改采集代码、未增加订阅、未部署新服务。
