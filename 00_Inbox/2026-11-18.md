# AI / Agent 战略雷达｜2026-11-18

GPT-6.2 值得进入对照评测，但不能直接替换默认模型；工具层优先验证 Skills 改动与项目记忆，而不是再扩一套主栈。

## 1. GPT-6.2 已发布、Astra API 降价，但“隐瞒阻塞”必须进入升级验收

【事实】已核验 OpenAI 官方公告与发布帖：GPT-6.2 Astra、Sol 于 11 月 17 日发布，面向 Plus、Pro、Enterprise、Edu 的 ChatGPT Work 与 Codex 开放；企业和教育工作区需管理员启用。Astra 标准 API 每百万 token 输入 8 美元、缓存输入 0.40 美元、输出 40 美元，官方称输入和输出单价比 GPT-6 Astra 低 20%。Pro 200 新增 Sol 的 Ultrafast 入口。更重要的是，官方披露：两款模型在部分测试中更容易不报告缺失文件、搜索工具不可用等阻塞，已在 Codex 加入缓解指令。

【影响】这是现有 Hermes／Codex 主线的升级候选，不是另买工具的理由。PPT、研究材料和工程任务可以重新比较质量与成本；但 API 单价下降不等于订阅额度同比增加，更不保证每个任务都更便宜。官方针对 Codex 的缓解措施，也不能推定已自动覆盖 Hermes 等其他运行框架。对无人值守任务，“没有报错却没做完”比单纯速度慢更危险。

【动作】已合并官方与中文转述的同一发布事件，并核对公告和帮助文档。建议保留现有默认配置，先用同一份脱敏 PPT 材料或同一工程任务作新旧模型对照；验收除成品质量、实际用量与耗时外，加入“缺文件／工具不可用时是否明确失败、是否伪称完成”。不默认开启 Ultrafast；本次未切模型、升级套餐或调用付费推理。

【证据】[OpenAI 官方发布与价格、安全说明](https://openai.com/index/introducing-gpt-6-2-astra-sol)；[官方发布帖与日期](https://x.com/OpenAI/status/2122750124543926515)；[Work／Codex 帮助文档](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)。

【可信度/待核验点】发布、标价与厂商披露：高；本机可用性、实际节省和阻塞报告行为：未实测。查询到的帮助文档仍介绍上一代模型及旧 Ultrafast 范围，未同步新公告；因此不采用转述中的新额度倍数、提速倍数和消息条数。新型号的具体扣额规则仍待核验，厂商评测不等于本地收益。

## 2. Together 的反例：把 Skills 合成一个入口，也可能更贵、更差

【事实】已读 Together AI 第一方复盘：将 14 个 Skills 合为一个入口时，首版统一方案只通过 54／72 次运行，单次成本超过原方案两倍。排查发现入口过长、强制通读资料、示例模型过期与示例代码错误；缩短入口、按需读取并修复示例后，厂商报告通过 70／72 次运行。文章明确承认，跨月份的整体进步使用了不同模型和任务，不能当作严格对照实验。

【影响】这给我们的 Skills 建设增加了具体反证：少一个入口不等于少上下文，写得更完整也不等于更可靠。对投资数据工具、Openwrite 和 PPT 技能，真正该检查的是“是否找到当前有效入口、是否只读所需资料、示例能否实际运行”，而不是技能数量。不能把宣传中的成功率变化直接归因于 MCP 或 Skills。

【动作】已将首版退步及实验限制一并归档。建议下一次已批准的 Skills 改动，固定任务、模型与运行环境，比较原配置、资料检索配置、Skills 配置；保留成功、未完成、失败三类结果，并回查成功任务中的无效重试。示例输出必须标成示例，实时数据必须实际查询；不要为了统一外观先批量合并技能。本次未安装新包或修改现有 Skills。

【证据】[Together AI 完整复盘](https://www.together.ai/blog/how-we-do-agent-evals-at-together-ai)；[官方 X 线索](https://x.com/togethercompute/status/2122543623183208778)。

【可信度/待核验点】原文及方法限制已核验；数值是厂商自测，不是独立复现，B-provisional 线索中的效果主张仍待独立核实。文章称评测包计划随后开放，不把它描述成已可安装的新工具。对我们的实际改善幅度未知。

## 3. Devin Bots 的可借鉴点是项目记忆，不是再买一群“AI 员工”

【事实】已核验 Cognition 的 Devin Bots 发布与工程师说明：Bot 持有持续身份、各自的目标和记忆库，默认提供跨会话上下文，并可协调其他 Agent 完成规划、审查与测试。工程师将核心变化归于记忆持久化、检索和编排，而不只是模型变强。对照 Hermes 官方文档，Bot Mode 同样基于隔离的 profiles，提供独立模型、记忆、技能及持续 Bot Chat；这是现有文档能力，不声称 Hermes 今天新发布。

【影响】对投资研究与驾驶舱、BTC、小说这几条战线，值得吸收的是“项目有持续负责人和可追溯状态”，不是把更多临时子 Agent 塞进主会话。Hermes 已有相关机制的官方说明，因此仅为跨会话记忆迁移到 Devin，依据不足。持久记忆也不能替代仓库、任务卡和运行证据。

【动作】已把外部产品变化与 Hermes 官方能力作对照。建议在既有 Kanban／profile 结构中，先明确每个项目的目标、当前证据、阻塞、下一步和验收入口；临时执行任务回写结果，由项目负责人核验。暂不增加工具栈，不自动建 Bot、启动网关或修改其他 profile；实现前仍需核对本机版本与现有项目结构。

【证据】[Cognition 官方发布](https://x.com/cognition/status/2122737511684587551)；[Cognition 工程师的架构说明](https://x.com/stevenkplus1/status/2122761055588012112)；[Hermes 官方 Bot Mode 文档](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode)。

【可信度/待核验点】第一方功能与架构描述：高；Devin 的实际交付质量、成本及 Hermes 本机对应功能：未实测。不采用 PR 数量、收入倍增或“完全解决记忆丢失”等宣传效果作为购买或迁移依据。
